简介¶
Go 是一门较新的语言。虽然它借鉴了现有语言的思想，但具有一些不寻常的特性，使得「地道」的 Go 程序在气质上不同于其近亲语言写出的程序。把 C++ 或 Java 程序直接翻译成 Go，往往得不到满意结果——Java 程序是用 Java 写的，不是 Go。另一方面，从 Go 的视角思考问题，可能写出成功但风格迥异的程序。换句话说，要写好 Go，必须理解其特性与惯用法；也要了解 Go 编程的既定约定（命名、格式、程序结构等），好让其他 Go 程序员容易读懂你的代码。

本文给出编写清晰、地道 Go 代码的提示。它补充语言规范、《Go 之旅》和《如何编写 Go 代码》，这些材料建议先阅读。

2022 年 1 月补充说明：本文写于 2009 年 Go 发布时，此后未大幅更新。尽管它仍有助于理解语言本身（得益于语言稳定性），但对库着墨很少，对此后生态的重大变化（构建系统、测试、模块、多态等）几乎未涉及。目前没有更新计划，因为变化太多，且已有大量文档、博客与书籍很好描述现代 Go 用法。《Effective Go》仍然有用，但读者应明白它远非完整指南。背景见 issue 28782。

示例¶
Go 标准包源码不仅是核心库，也是如何使用语言的范例。此外，许多包包含可运行的独立可执行示例，可直接在 go.dev 网站运行（如有需要，点击 “Example” 展开）。若你想知道如何着手某问题或某功能可能如何实现，库中的文档、代码与示例往往能提供答案、思路与背景。

格式¶
格式问题最容易引起争论，却最无关紧要。人们可以适应不同格式风格，但最好不必适应；若大家遵守同一风格，花在这上面的时间更少。问题是：如何在没有冗长规定性风格指南的情况下接近这一理想。

Go 采取了不寻常的做法：让机器处理大部分格式问题。`gofmt` 程序（也可用 `go fmt`，作用于包级而非单文件）读取 Go 程序，按标准缩进与垂直对齐输出源码，并保留、必要时重排注释。若遇到新的排版情况，先跑 `gofmt`；若结果不对，调整程序结构（或给 `gofmt` 提 bug），不要绕过它。

例如，不必花时间对齐结构体字段旁的注释。`gofmt` 会替你完成。给定声明：

```go
type T struct {
    name string // name of the object
    value int // its value
}
```

`gofmt` 会把列对齐为：

```go
type T struct {
    name    string // name of the object
    value   int    // its value
}
```

标准包中的全部 Go 代码都已经过 `gofmt` 格式化。

仍有一些格式细节。简要说明：

缩进  
默认用制表符缩进，`gofmt` 默认也输出制表符。非必要不要用空格。

行长  
Go 没有行长限制。不必担心「打孔卡片溢出」。若一行感觉太长，换行并用额外制表符缩进。

括号  
Go 比 C 和 Java 需要更少括号：控制结构（`if`、`for`、`switch`）语法上没有括号。运算符优先级层次也更短更清晰，因此：

```go
x<<8 + y<<16
```

含义与空格所暗示的一致，这点与其他语言不同。
